# TikWave Premium Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** Pubs pour les gratuits, abonnement Stripe à 2,99 €/mois, clés d'accès offertes par l'admin, le tout vérifié côté serveur.

**Architecture :** `server.py` (un seul fichier, on suit la structure existante) calcule le statut Premium (admin, clé ou Stripe) et l'impose dans `/api/extract`. Le webhook Stripe relit l'abonnement chez Stripe puis applique son état. `index.html` affiche pubs, feuille Premium et profil à partir de `premium_exp` et `paywall` renvoyés par le serveur.

**Tech Stack :** Flask, SQLAlchemy (SQLite/PostgreSQL), SDK `stripe` (appels sortants uniquement), JS vanilla, pytest + Playwright pour les tests.

**Spec :** `docs/superpowers/specs/2026-11-24-premium-design.md`

## Global Constraints

- Tout le texte d'interface est en français, ton « tu » comme l'existant.
- Aucune clé dans le code : `STRIPE_SECRET_KEY`, `STRIPE_PRICE_ID`, `STRIPE_WEBHOOK_SECRET`, `ADMIN_EMAIL` (liste séparée par des virgules, insensible à la casse), optionnelle `PUBLIC_URL`.
- Paywall actif seulement si `STRIPE_SECRET_KEY` **et** `STRIPE_PRICE_ID` **et** R2 sont configurés ; sinon comportement identique à aujourd'hui.
- Premium actif si admin **ou** `gift_until` > now **ou** `premium_until` + 48 h (`PREMIUM_GRACE = 172800`) > now. À vie = `FOREVER = 4102444800`.
- Pub tous les `ADS_EVERY = 5` sons ; liste unique `ADS` dans `index.html` ; liste vide = aucune pub ; aucune pub hors ligne ni pour un Premium.
- Clés : format `TKS-XXXX-XXXX-XXXX` (alphabet sans `0 O 1 I L`), hachées avec HMAC(`SECRET`), jamais renvoyées après la création, 10 essais de `/api/premium/redeem` par heure et par IP.
- SQL portable SQLite/PostgreSQL (`BIGINT`, pas de `INSERT OR IGNORE`).
- Les fichiers du projet restent : `server.py`, `index.html`, `sw.js`, `requirements.txt` (+ `stripe>=10.0`).
- Pas de dépôt git ici : le baseline est copié dans `/home/claude/baseline/` pour les diffs.

## Review Focus

1. Webhook rejoué ou arrivé dans le désordre (`payment_failed` après `paid`) : l'état final reste celui de Stripe (Task 4).
2. Webhook non signé, signature périmée ou corps modifié : refusé, base inchangée (Task 4).
3. Suppression de compte avec abonnement actif : Stripe résilié d'abord, et si la résiliation échoue le compte n'est pas supprimé (Task 4).
4. Pub dont l'audio ne charge pas, ou clic sur suivant/précédent/lecture pendant la pub : la musique reprend seule, jamais deux audios en même temps (Task 7).
5. Résiliation Stripe pour un utilisateur qui a aussi une clé : il reste Premium ; clé révoquée : il le perd (Tasks 3 et 4).

### Task 4: Stripe (checkout, portail, webhook, suppression de compte)

**Files:** Modify `server.py` (+ `delete_me`) ; Modify `requirements.txt` ; Test `tests/test_stripe.py`

**Interfaces:**
- Adaptateur SDK (une fonction de ≤ 6 lignes chacune, importe `stripe` à l'appel, remplaçable dans les tests) : `stripe_create_customer(email: str, user_id: str) -> str` ; `stripe_create_checkout(customer_id: str, user_id: str, base_url: str) -> str` (mode `subscription`, `STRIPE_PRICE`, `client_reference_id=user_id`, `locale="fr"`, retours `?premium=success` / `?premium=cancel`) ; `stripe_create_portal(customer_id: str, return_url: str) -> str` ; `stripe_get_subscription(sub_id: str) -> dict` (dict simple) ; `stripe_cancel_subscription(sub_id: str) -> None` ; `stripe_get_price() -> dict`.
- Purs : `verify_stripe_signature(payload: bytes, header: str, secret: str, tolerance: int = 300, now: float | None = None) -> bool` (schéma Stripe : `t=…,v1=…`, HMAC-SHA256 de `"{t}.{payload}"`, comparaison à temps constant, plusieurs `v1` acceptés) ; `sub_id_from(obj: dict) -> str | None` (essaie `subscription`, `parent.subscription_details.subscription`, ligne de facture) ; `period_end(sub: dict) -> int` (`current_period_end` ou max des `items.data[].current_period_end`) ; `apply_subscription(conn, sub: dict) -> None` (actif/essai → `premium_until = period_end`, `plan_status`, `cancel_at_end`, `stripe_sub_id` ; tout autre statut → `premium_until = 0`, **sans toucher `gift_until`**).
- Routes : `POST /api/stripe/checkout` → `{url}` (401 ; 503 paywall off ; 409 déjà abonné actif avec `portal: true` ; client Stripe créé une seule fois via `UPDATE … WHERE stripe_customer_id=''`) ; `POST /api/stripe/portal` → `{url}` (404 sans client) ; `POST /api/stripe/webhook` (corps brut, 400 si signature invalide, 200 sinon).
- Webhook : événements `checkout.session.completed` (mode `subscription`), `invoice.paid`, `invoice.payment_failed`, `customer.subscription.updated`, `customer.subscription.deleted` ; autres → 200 « ignored ». On retrouve l'utilisateur par `stripe_customer_id` (repli : `client_reference_id`), on relit l'abonnement par `stripe_get_subscription`, puis dans **une seule transaction** : `INSERT INTO stripe_events` (conflit de clé = déjà traité → 200) + `apply_subscription`. Échec Stripe ou base → 500 sans enregistrer l'événement (Stripe réessaiera). Utilisateur inconnu → 200 + log.
- `delete_me` : si `stripe_sub_id` et Stripe configuré, `stripe_cancel_subscription` avant toute suppression ; erreur → 502, compte conservé.
